# Plan: v0.12.0 release remediation

Base: `19d2c55`. The cleanup candidate includes the selected dev-review fixes,
the contributor-guidance correction, and the current bounded Rust patch group.

## Release blockers

1. **Security lock refresh.** Update the lockfile from vulnerable `rustls`
   0.23.41 to the patched compatible release and move `event-listener` off the
   known-unsound 5.4.1 release. Re-run the repository security workflow locally
   where possible and require the hosted `dependencies-and-secrets` check.
2. **Visible startup failure.** Replace the log-only storage-open failure path
   with a native error dialog that can be shown before the Tauri service is
   available. Keep the message non-destructive and avoid exposing filesystem or
   secret details.
3. **Packaged preview acceptance.** Build the macOS application with updater
   artifacts disabled, launch it against disposable data, import a synthetic
   image or PDF, and verify the blob-backed preview on the packaged webview.
4. **Release records.** Put all not-yet-published fixes in the 0.12.0 changelog
   section, refresh the verification ledger with exact candidate evidence, and
   keep unresolved platform limits explicit.

## Implemented locally

- The lockfile selects patched compatible releases of `rustls`,
  `rustls-webpki`, and `event-listener`.
- Desktop startup reports storage-open failures with a native dialog before it
  exits; guided retry and recovery remain outside this release.
- The unpublished fixes are recorded under 0.12.0 with the intended release
  date. Packaged preview and startup-failure acceptance remain release gates.
