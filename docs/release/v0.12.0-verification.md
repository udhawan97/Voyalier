# Voyalier v0.12.0 verification ledger

This ledger records the release candidate's implemented scope and the evidence
needed to publish it. It separates product behavior Voyalier owns from live
provider behavior that remains on third-party or official sites.

## Publication gates

Before the draft becomes public:

1. Complete the two-round council record with no material blocker.
2. Pass GitHub branch checks and the keyless macOS/Windows release dry run on
   the exact candidate commit.
3. Pass the opt-in Windows installed-app, updater-swap, data-preservation and
   reinstall-recovery job on that commit.
4. Build the protected tag, then verify both updater platform keys, updater
   signatures, checksums and GitHub provenance attestations in the draft.
5. Confirm `packs-v1` remains a pre-release and its city-pack artifacts remain
   intact before publishing v0.12.0.
6. Confirm the protected tag, published release and `origin/main` resolve to the
   same release commit.
7. Verify the live documentation and download surface after publication rather
   than treating the local static build as public evidence.

The macOS source-build pass remains separate from the protected updater-swap
checks. It proves the locally signed candidate launches and exposes the intended
installed webview; it does not replace the platform updater evidence.
